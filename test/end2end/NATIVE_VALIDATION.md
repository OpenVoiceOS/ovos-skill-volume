## Known routing bugs (reproduced, not coverage gaps)

Found while building the Tier-1 floor. Root cause: the skill's own adapt
intents (`current_volume` requires only the `volume` vocab word;
`change_volume` requires `change`+`volume`; `increase_volume`/`less_volume`
require `louder`/`quieter`+`volume`) run in the `*-high` pipeline tier ahead
of `ovos-padacioso-pipeline-plugin-high`, and fire on any utterance that
merely contains one of those vocab words — shadowing the more specific
`volume.high/low/max.intent` padatious/padacioso matches.

- [ ] de-DE "Lautstärke hoch" — claimed by `current_volume`, should be `volume.high.intent`
- [ ] de-DE "stell die Lautstärke auf leise" — claimed by `current_volume`, should be `volume.low.intent`
- [ ] fr-FR "augmente le volume" — claimed by `increase_volume`, should be `volume.high.intent`
- [ ] fr-FR "baisse le volume" — claimed by `less_volume`, should be `volume.low.intent`
- [ ] it-IT "Alza il volume" — claimed by `increase_volume`, should be `volume.high.intent`
- [ ] it-IT "Abbassa il volume" — claimed by `less_volume`, should be `volume.low.intent`
- [ ] nl-NL "hoog volume" — claimed by `current_volume`, should be `volume.high.intent`
- [ ] pt-PT "volume baixo" — claimed by `current_volume`, should be `volume.low.intent`
- [ ] ca-ES "volum alt" — claimed by `increase_volume` (`alt` is in `louder.voc`), should be `volume.high.intent`
- [ ] da-DK "høj lydstyrke" — claimed by `current_volume`, should be `volume.high.intent`
- [ ] da-DK "lav lydstyrke" — `change.voc` entry `lav` ("make") collides with the
      Danish adjective `lav` ("low"); claimed by `change_volume` (then crashes
      on a `get_response()` follow-up on the bare test harness), should be
      `volume.low.intent`
- [ ] en-US cross-language negative: "volume máximo" (a pt-PT phrase) in an
      en-US session is claimed by `current_volume` — the bare "volume" match
      has no language gate

These are pinned in `test/end2end/test_golden_utterances_multilang.py`
(see `KNOWN_BUGS` / `KNOWN_NEGATIVE_BUGS`): the test only calls
`pytest.xfail(reason=...)` when the row is confirmed to still not match, and
otherwise falls through to a normal `assert matched`. That means the suite
documents the bug without hiding it, and goes red the moment the bug is
fixed (the row then hits the ordinary assertion, requiring the row be
dropped from `KNOWN_BUGS`/`KNOWN_NEGATIVE_BUGS` instead of staying green by
convention).

## fa-IR — top-line finding, not testable

`locale/fa-IR/` ships only `skill.json` (marketplace/store metadata) — no
`.intent` or `.voc` files. The skill has no Persian vocabulary or intent
templates to route on, so there is nothing for this suite to test. This is
called out here rather than silently skipped. No Persian intent/vocab
content is added by this suite.
